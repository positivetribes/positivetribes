# Tribe Hub notes (loaded only when working in hub/)

Moved from ~/.claude/CLAUDE.md to save tokens on every request. Global rules (security, Salesforce logging, email, subagent models) still apply.

The hub is Positive Tribes' one shared workspace for every client and for Eric's own command center. Know how it works, use it as a source of truth next to Salesforce, and keep this section accurate.

- **What it is:** a Cloudflare Worker named `tribe-hub` (code in `/Users/eroberts/Projects/PositiveTribes/hub/`, with `hub/README`-style notes in `PositiveTribes/README.md`). Static single-page app in `hub/public/` (`index.html`, `command.js`) with hash routes, API in `hub/src/` (`index.js`, `admin.js`, `notifications.js`, `salesforce.js`, `access.js`). No workers.dev address; it is only reachable at hub.positivetribes.org.
- **Sign-in:** Cloudflare Access with One-time PIN. Adding a client user takes two steps: a `users` row, and their exact email in the reusable Access policy "Hub Users" (Zero Trust > Access controls > Policies; also used by the positivetribes.org/admin app). Without the policy entry, Cloudflare says the code was sent but sends nothing and logs nothing (Mandy at WFA, 2026-11-20). People are matched by email to the `users` table (roles: `ed` = client executive director, `staff` = client staff, `pt` = Positive Tribes, all clients). The daily sync routine uses an Access service token and may call only `GET /api/admin/match` and `POST /api/admin/activity`.
- **Client side** (`#/<client-slug>/...`): *What's next* (home: project phases, releases, testing windows, documents), *Questions & changes* (the backlog: questions, changes, problems, requests, each with tier must/nice/idea, phase review/prototype/full/later, owner, answer, due date, done, UAT sign-off), and *Improve this hub* (ideas, with Positive Tribes replies; opened from the lightbulb button in the top bar). A bell shows notifications (added, answered, done, phase moves, sign-offs, UAT started, live, shared documents, idea replies; testing-window-ending reminders pinned). On the home page, a project with several client phases spans the row with its phases side by side, and the others sit beneath; "all caught up" is one slim line. The "Your next step" card is a queue (2026-11-26): the viewer's open questions (first must-have leads, then soonest due), else one must-fix problem; with two or more it shows ‹ "N of M" › to step through them (`nextCard` in `public/index.html`, `state.focusId`/`focusAt`, front end only). Stepping updates the card in place, never `render()`, so the live region (position and title) and text typed elsewhere on the page survive, and a background redraw puts focus back on the arrow. The lead shows until the viewer steps, so a new must-have takes the card on the next refresh. "Waiting on you" on the home page leaves out every question the arrows reach. Owner matching (`ownedBy`) is whole words since then, split on spaces and separators only ("Al" no longer matches "Sally"; "Jen" no longer matches "Jennifer"). A *System status* card on a client's home (one folded line, "All systems running", while every check is up; the full card when anything is not) shows live up/down and 90-day uptime for that client's apps, fetched server-side from the `tribe-status` Worker's public JSON (`GET /api/c/<slug>/status`, `STATUS_URL` var; empty if the client has no checks). Old backlog sites (UEP, Project Coyote) now forward here and refuse changes (`MOVED_TO`); their databases are kept for history.
